# Signet OpenCode V2 lifecycle plugin

This local plugin was ported from Signet `0.226.27`, source revision `b8b0c5641e3d90c8b4622f78cfd6cff1877b2a73`, to OpenCode V2.0.16. Its checkpoint and session-end contracts were also reviewed against Signet `0.230.8`, revision `df33b037300114abcd70b5bc2b7bd06366b5deb0`. The repository source is `/repo/openchamber/plugins/signet-opencode-v2`; host registration in `/home/core/.config/opencode/opencode.jsonc` is managed separately. It uses documented V2 Promise plugin hooks. Its exact dependencies are locked in `bun.lock`; compatibility with a newer installed OpenCode CLI is not established merely by that CLI's version. Upstream Apache 2.0 licensing and local port attribution are retained in `LICENSE` and `NOTICE`.

## Restored behavior

The plugin restores workspace and per-session `session-start`, `user-prompt-submit`, notification refreshes, `pre-compaction`, `skill-invocation`, and `compaction-complete`, with transcript checkpoints for finished executions and `session-end` for actual deletion. It maps prompt admission to `ctx.session.hook("prompt")`, model input to the documented request hooks, tool hooks to `ctx.tool.hook`, and lifecycle events to `ctx.event.subscribe`. V2 session identifiers and parent IDs are read from `event.data`; compaction completion uses `session.compaction.ended` and its `data.text`. Session-scoped calls and transcript reads require the session's directory to match the plugin location. Prompt work is single-flighted by session/message ID. Execution success, failure, and non-shutdown interruption send checkpoints and clear the finished turn's local context; shutdown interruption preserves resumable work. Deprecated `session.idle` is supported only until modern execution events are observed for the session. Public event IDs deduplicate repeated deliveries; they are not treated as prompt/run correlation IDs.

Stable workspace/session context and notification text are added idempotently to V2 request system parts. Dynamic prompt context uses the V1 `<signet-memory>` wrapper and is added to the matching user message in the V2 `context`, `compaction`, `generate`, and `title` request hooks. ID-less initial-title drafts must exactly match the admitted prompt's original text; conflicting message IDs and synthesized history are not injected. The plugin records the exact text it injected for each turn and system context, so it replaces its own previously produced text in repeated or cloned request drafts without deleting user-authored marker text. Compaction guidelines are added to the compaction request's system context. The validated per-turn clock string is appended to the matching request message. Context is not added to the V2 `prompt` event or persisted as a durable user message: the V2.0.16 model-request pipeline builds a transient request draft from history before these hooks run. A system-level instruction labels Signet material as private, untrusted reference context and asks the model not to disclose it; this is defense-in-depth, not an output sanitizer.

At an execution checkpoint, the plugin reads the public OpenCode V2.0.16 `GET /api/session/{sessionID}/message` API using `order=asc` on the first page, `limit`, and opaque `cursor.next` pagination. Continuation cursors encode ordering and must not be combined with an `order` parameter. A non-empty page can return a next cursor even below its limit; an absent or null next cursor is terminal, including the following empty page. The plugin submits a transcript only if pagination completes within 50 pages, 10,000 messages, 2 million transcript characters, 4 MB per API page, and a 15-second end-to-end timeout. Only user and assistant text is included. Request-draft injections are not persisted in V2, so stored transcript text is preserved instead of stripping marker-shaped user text without provenance; older persisted injected context cannot be reliably distinguished from user-authored content. Missing authentication, an unavailable API, HTTP/parse errors, repeated cursors, or a reached bound omit the transcript rather than submit partial history. The API base defaults to `http://127.0.0.1:4096`; configure `openCodeApiBaseUrl` to match a non-default loopback listener. `OPENCODE_PORT` is also honored as a local port override when it matches the listener. OpenCode V2.0.16 can advance to another port when the default is occupied, so configure the actual listener address explicitly in that case. Plain HTTP is allowed only for loopback. Remote API access is disabled unless the base URL is HTTPS and the process environment variable `SIGNET_OPENCODE_API_TRUSTED_ORIGIN` exactly matches its origin (scheme, host, and port); the value must be an origin, with no path or credentials. Requiring an explicit process-environment trust value prevents a project plugin option from authorizing credential disclosure. Redirects are rejected so HTTP Basic credentials are not forwarded to another destination.

The transcript request reads `OPENCODE_SERVER_PASSWORD` and, when set, `OPENCODE_SERVER_USERNAME` only from the plugin process environment; the V2 service's documented default username `opencode` is used otherwise. Credentials are never read from plugin options/config, embedded in source, logged, or included in output. Tests inject synthetic environment values and fake fetch implementations. Workspace `session-start` failure restores the V1 best-effort static identity fallback from `SIGNET_PATH` or `~/.agents`, with distinct offline and timeout status text; an explicit identity mode of `off` is respected.

Finished executions send `session-checkpoint-extract` with the supported `project` field, not a false `session-end`. Signet `0.230.8` intentionally ignores ordinary-turn transcripts passed to `session-end`; that route can also temporarily suppress a later real deletion through its session tombstone. Checkpoint snapshot retention depends on Signet's pipeline being enabled or in shadow mode. Its `{ skipped: true }` response is not a durable-persistence receipt, a completed-transcript marker, or a promise of semantic memory extraction after every reply. Real deletion sends `session-end` with `reason: "session.deleted"` and `cwd`, without attempting to read history that OpenCode has already deleted. Signet can use an earlier retained snapshot for capture, but a tail never retained cannot be recovered through the deleted session's public API.

The public history API has no historical snapshot or execution correlation input. Checkpoint transcript preparation is tracked separately from the ordered event controls, so a successor's execution-start notification is not blocked by an earlier history read. Prompt admission, execution starts, and model-hook activity after a pending terminal advance local activity, including resume and synthetic paths without a prompt hook. Superseded preparations neither submit the successor's partial transcript nor clear its state; the later terminal can submit fresh history. Once a checkpoint or end POST is dispatched, the next session-start and prompt submission wait for that report to settle. Reports for the same session are ordered and retain the 10-second write timeout; cleanup rejects late preparations and releases waiting admissions without dispatching new work. These are local generation and request-ordering guards, not an atomic snapshot or transactional server guarantee. A network timeout does not prove that an already accepted daemon mutation was cancelled.

Existing `SIGNET_ENABLED=false`, `SIGNET_NO_HOOKS=1`, daemon URL, agent ID, and timeout settings remain supported. Daemon POSTs reject redirects so prompt text and an optional bearer token are not forwarded to a redirect target. Daemon failure and timeout do not fail prompt admission. The event stream is live-only and has no documented automatic reconnect, so the plugin does not retry subscription failures.

Successful setup logs the non-sensitive marker `[signet.lifecycle] loaded revision 2026-10-04.4` and the OpenCode version, without memory text or credentials. Local source changes are watched and hot-reloaded by OpenCode V2.0.16; they do not require a server restart. Reload replaces hooks and clears transient plugin state, so prefer an idle point when deliberately reloading. Check the setup marker and matching local-source failures in the plugin inventory rather than treating an `active` row alone as proof of the revised code. Installed npm dependency changes can still require a service restart because their module cache is not invalidated with local sources.

## Upstream compatibility

Signet commits [`5ea9319`](https://github.com/Signet-AI/signetai/commit/5ea9319371212b85210b13522225a00002135946) and [`403ddf6`](https://github.com/Signet-AI/signetai/commit/403ddf6509ff85ec554e17204cd5f8614c0cc6e4) update Signet's workspace-v2 path resolution, not OpenCode's V2 plugin API. Their OpenCode plugin still uses `@opencode-ai/plugin`, an async `PluginInput` entrypoint, `event.properties`, and V1 hook names. The versioned `0.230.8` source retains that API. OpenCode's V2 migration guide explicitly requires porting V1 plugins, so these workspace changes alone do not make the upstream plugin a replacement for this port. Its configurable workspace resolver is a separate fallback-path improvement; this port currently preserves `SIGNET_PATH` or `~/.agents` for static identity.

On 2026-10-04, the official stable channel was `0.157.3` at revision `94c3075d09156d89328d9fc6aa4ad8a5efdfe0ff`, and nightly was `0.230.9` at `d1880536342edb4b5fbe211dfa4de4f8b274a404`. Downloaded npm connector artifacts and release Linux CLI binaries contained the same V1 plugin for each channel; registry SHA-512 and release-manifest SHA-256 checks passed. The upstream plugin is embedded in `@signetai/connector-opencode`, whose installer writes `~/.config/opencode/plugins/signet.mjs`, rather than being independently published as `@signet/opencode-plugin`. Neither inspected channel provides a V2 replacement. Artifact inspection did not execute an upstream plugin in V2 or establish compatibility for uninspected branches. The running daemon's `0.230.8` version is distinct from these release-channel labels.

## Assistant-output sanitization limitation

The V1 `experimental.text.complete` hook scrubs final assistant text with `scrubPromptContext` and `stripInternalMemoryContext`. OpenCode V2.0.16 has no documented assistant-text-complete hook. It documents `http.response` and experimental WebSocket receive hooks, but those expose provider-specific JSON/SSE bodies or protocol frames before OpenCode decodes them. Rewriting them cannot provide a provider-independent, protocol-safe final-text scrub, so the plugin does not register them. Its strongest supported privacy guard is to escape Signet context delimiters, label Signet context as private and untrusted, and instruct the model not to reveal it verbatim or by paraphrase; this is defense-in-depth, not output sanitization or a guarantee. Signet memory, notifications, and compaction context are restored, but the V1 final-output scrub is not. Do not use this lifecycle plugin where a final-response disclosure guarantee is required; remove its `plugins` entry or set `SIGNET_NO_HOOKS=1` and restart `opencode.service` to disable the hooks while keeping the remote Signet MCP available.

## Source, bundle, and verification

From this directory, run `test -s bun.lock && bun install --frozen-lockfile && bun run test && bun run build` with Bun `1.4.2`. The frozen suite contains 48 tests and 504 assertions. Tests use synthetic identity files and injected fake daemon and OpenCode API fetch functions; the redirect regression also starts a temporary loopback HTTP server with synthetic prompt/token values to exercise real fetch behavior. They do not contact the actual Signet or OpenCode services or read persisted session/memory data. The `@opencode/plugin` and `@opencode/client` API dependencies are pinned to V2.0.16.

`package.json` retains `main: ./index.ts`, so host registration continues to load source; building or downloading the artifact does not silently switch registration to the bundle. `bun run build` produces `dist/signet-opencode-v2.mjs` with Bun target/ESM format and an external `@opencode/plugin` import. The bundle includes `yaml@2.6.0` under its actual ISC license, retained in `yaml-LICENSE`. It is not a self-contained OpenCode runtime and must be imported where the API-compatible `@opencode/plugin@2.0.16` dependency can resolve.

The repository's `main`-push CI repeats the frozen install, unit suite, bundle build, and bundle export import. It retains the bundle with SHA-256 checksum, source commit metadata, and licenses/notices as a private Actions artifact for 30 days. CI does not start OpenCode or a Signet daemon, deploy the plugin, run strict TypeScript checking, or certify newer OpenCode versions. Separately recorded acceptance on 2026-10-04 passed strict TypeScript checks and an isolated OpenCode V2.0.16 smoke covering native hooks/model requests, persisted history pagination, checkpoint submission, and deletion with the final `2026-10-04.4` source. That smoke used isolated test state and is not a claim that CI or the live host repeated it; it does not remove the final-output sanitization limitation above.
